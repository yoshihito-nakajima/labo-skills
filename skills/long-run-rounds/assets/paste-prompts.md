# 貼付文の雛形

`<…>` を埋めて、本文スレッドとレビュー・スレッドにそれぞれ貼る。規則は指示書に置き、貼付文には書かない。
動いているスレッドに貼り直してもよい（指示書を読み直し、自分の定期再開を作り直す）。
新しいスレッドに貼るときは、先に古いスレッドを止める。

## 本文用

```text
これはユーザーによる<教材名>本文の明示再開指示です（指示書は<日時>に改訂しました）。あなたは<範囲>の本文・統合の親です。方針は、<方針の列挙：自走（ユーザーに聞かず推奨で決める）、自己完結、迷ったら採る、前の冊から順に、容量を見ながら>、です。いまの最優先は<現在地の一句>です。
<指示書の絶対path> を開き直し、§0〜§5 だけを読んで、§2「開始時」から手順どおりに実行してください（§6はworker用なので読まなくてよい。このスレッドで前に読んだ内容ではなく、いまのファイルに従ってください）。
親は割り振り・待機・一行記録だけをし、本文・report・原著は読まず、中身の仕事は全て指示書の依頼文でworkerに渡してください。依頼文は§5の文を書かれたとおりに渡し、行を足したり言い換えたりしないでください。workerには状況表示に出る model・subagent_type・effort を必ず明示し、run_in_background は false にしてください。
毎回、状況表示の「容量の段階」を先に見て、§3のとおりに動いてください。上限に当たっても定期再開は消さないでください。
私に質問や判断依頼をせず、判断はworkerに指示書の規則で決めさせてください。一周やbuildが終わっても最終回答を出さず、次のworkerを出し続けてください。止めてよいのは、§3の表に従ったWAIT・ALL_DONE、容量の段階による待機、実際の上限到達、私の停止指示だけです。
```

## レビュー用

```text
これはユーザーによる<教材名>レビューの明示再開指示です（指示書は<日時>に改訂しました）。あなたは<範囲>のレビュー親です。方針は、<方針の列挙>、です。いまの最優先は<現在地の一句>です。
<指示書の絶対path> を開き直し、§0〜§5 だけを読んで、§2「開始時」から手順どおりに実行してください（§6はworker用なので読まなくてよい。このスレッドで前に読んだ内容ではなく、いまのファイルに従ってください）。
親は割り振り・待機・一行記録だけをし、本文・report・原著は読まず、選定・確認は全て指示書の依頼文でworkerに渡してください。依頼文は§5の文を書かれたとおりに渡し、行を足したり言い換えたりしないでください。気づいたことは記録に一行書くだけにしてください。workerには状況表示に出る model・subagent_type・effort を必ず明示し、run_in_background は false にしてください。
毎回、状況表示の「容量の段階」を先に見て、§3のとおりに動いてください。上限に当たっても定期再開は消さないでください。
私に質問や判断依頼をしないでください。候補0やqueue空で最終回答を出さず、待機と定期再開を続けてください。止めてよいのは、§3の表に従ったWAIT・ALL_DONE、容量の段階による待機、実際の上限到達、私の停止指示だけです。
```

## 使い方の説明（ユーザーへ渡す紙に添える）

- 2つのスレッドを低いモデル（親は軽い段階）で立て、それぞれに貼る。順番はどちらでもよい。
- 放っておいてよい。スレッドはユーザーに質問しない。容量の段階を見て節約・待機する。
- 止めたいときは、そのスレッドに「止まれ」と書く。
- 進み具合は状況表示の道具で見る。
