# 状況表示の契約

親が毎回見るのは状況表示の出力だけ。親は本文や report を読まないので、
**親の判断に要る事実はすべてこの出力に一行で出す**。この契約の実装が
[round_status.py](../scripts/round_status.py)（`--config <project>.json <role>`）で、プロジェクトの固有情報は設定 JSON に置く。
読むだけで（容量の較正ファイルの追記を除く）、10秒程度で終わり、補助の計算が失敗しても表示を止めない。
欄を足すときはこの表と script を一緒に直し、その欄を FINGERPRINT にも入れる。

## 出す欄（上から）

| 欄 | 中身 | 誰の仕事かの注記 |
|---|---|---|
| 容量の段階 | `usage_window.py --calib <file> --learn --json` の stage・割合・窓の終わり、最後の上限と解除時刻 | 段階ごとの動き一句 |
| worker 役割 | 役ごとの subagent_type・model・effort（プロジェクトの設定ファイルから） | 「必ず明示で渡す」 |
| queue | 制作側の状態、完了フラグ、最終bundle | |
| 最近の case | 再開日以降の case を実物（ディレクトリ）と queue の作者状態から分ける：返却済み・作者未閉鎖／修復済み・再確認待ち／claim中・未返却／公開・未claim／queue未登録 | 各欄に「本文側の仕事」「レビュー側の仕事」「待つだけ」 |
| 採用範囲の照合 | 冊ごとの照合表の状態の数（TODO・MISSING・PARTIAL・OK・OUT）と `CLOSED:` 行 | |
| 公式出力 | 冊ごとの PDF の mtime・頁・hash 先頭 | |
| 正本の最終書込 | 最後に書かれた正本ファイルと時刻 | |
| 排他 lock | 重い証明用 lock の有無と時刻 | |
| 今の冊の被覆 | 閉じていない最初の冊について、`review_coverage.py summary --json` の未確認・確認後に変更・確認中・軽微修復で確認済み | |
| 整理の済否 | 溜まった「確認後に変更」の整理が済んだか（記録ファイルの決まった一行で判定） | 「未」で件数があれば「本文側は WAIT にしない」 |
| 置き場所違い | 決まった場所以外に作られた case | `!!` と移し方 |
| レビュー側だけ | 冊ごとの被覆の要約、次の候補の数と「安定」の数 | |
| FINGERPRINT | 下の材料の hash 先頭 | 「WAIT の行に書き、同じなら worker を出さない」 |
| 記録の末尾 | 自分の役の記録の末尾数行、相手役の引継ぎの末尾 | |

**分け方の注意**：作者が直して再確認を待っている case（queue の `repaired`）を「返却済み・作者未閉鎖」に数えると、
本文側の親が WAIT を却下し続けて空回りする。待つだけのものは別の欄にする。

## FINGERPRINT の材料

待機中の親は、FINGERPRINT が前回の WAIT と同じなら何もしない。だから**状況が変わったら必ず変わり、
変わっていなければ変わらない**材料だけを入れる。

- queue ファイルの hash、相手役の引継ぎファイルの mtime、正本の最終書込時刻、公式出力の mtime
- 最近の case の分類、照合表の数
- レビュー候補の位置と「安定」かどうか（安定に変わったことも新着）
- 今の冊の被覆の数と整理の済否、置き場所違いの一覧
- 容量の段階（数値は入れない。段階が変わったときだけ起きる）
- 最後の WAIT からの経過時間（時間単位）。新着がなくても1時間ごとに一度 worker が出て、取りこぼしを拾う

## 安定条件

レビュー側は、対象ファイルの最終書込から一定時間（例：15分）たった範囲だけを固定する。長すぎると、作者の
小さな修復のたびにレビュー側が待たされる。軽微な修復を記録する（`review_coverage.py record-repair`）運用なら、
書込は減るので短くしてよい。
