# 失敗と規則

無人ラウンドで実際に起きた失敗と、それを防ぐ規則。指示書の §1「経緯」に書く形の元になる。
見守るとき（[SKILL](../SKILL.md) の手順5）は、この見分け方で記録と状況表示を見る。

| 失敗 | 見分け方 | 規則 |
|---|---|---|
| 選択欄の親モデルと実行中のモデルが食い違う | 保存済みモデルに対し実行ターンのモデルが異なる | 初回・継続・再開の各ターンで照合し、指定外または確認不能なら受付と配付を止める |
| 採用範囲を照合せずに「完了」と宣言する | 頁数が計画の想定より大きく少ない。完了の根拠が「queue が空」 | 完了は冊ごとの照合表が閉じたときだけ。照合は原著の側から番号ごとに |
| 照合が「その語が PDF にあるか」の存在確認で済む | 節一つが一行で OK、頁の欄が空の OK | OK は定義・主張・証明までその冊の PDF にあるときだけ。頁を書けない OK は PARTIAL |
| 採否が決まらず「ユーザー判断待ち」で止まる | BLOCKED の理由が判断待ち | 採否の三段の規則で worker が決めて記録する。BLOCKED は技術的な障害だけ |
| 親が自分の worker の記録を「別のセッションの作業」と取り違えて止まる | 親の記録に「他の編集を待つ」 | 記録の worker 行と正本の書込は自分の worker のもの、と指示書に書く |
| 軽微な所見だけの再照合を何版も回す | 同じ照合 packet の v が増え、所見が軽微だけ | 再照合は重大・中を直したときだけ |
| 軽微な修復のたびに被覆が「確認後に変更」に戻り、出し直しが続く | 閉じる条件の「確認後に変更」が減らずに増える | `record-repair` で軽微な修復を記録し、確認済みと数える。溜まった分は一度整理する |
| 規則を足しても worker が使わずに WAIT を返す | 状況表示に仕事があるのに WAIT が続く | 新しい仕事は WAIT の条件にも書く。状況表示に「本文側は WAIT にしない」の注記を出し、親の却下条件にする |
| 待つだけの case を「本文側の仕事」に数え、WAIT の却下と待機を繰り返す | 却下の直後にまた WAIT、が続く | 状況表示で「修復済み・再確認待ち」を分ける |
| 成果物を決まった場所以外に作り、被覆に数えられない | 確認したのに未確認の数が減らない | 依頼文の path を絶対 path にする。状況表示が置き場所違いを `!!` で出す |
| 作者の書込が続き、レビューの安定条件で長く待つ | レビュー側の WAIT の理由が「未安定」 | 安定条件を短くする。軽微な修復を記録して書込を減らす |
| 今の冊が閉じる前に後ろの冊を埋める | 後ろの冊の補完の記録 | cursor は閉じていない最初の冊。先に進めてよいのは次の冊の照合だけ、余裕のときだけ |
| 5時間の上限で worker が途中で切れ、親が止まったまま残る | 記録が上限の知らせで終わる | 容量の段階で先に仕事を絞る。定期再開は消さない。解除後に片付けてから続ける |
| 新しいスレッドで始め直し、古いスレッドの定期再開が残って親が二人になる | 同じ役の開始行が二つ、記録が交互 | 定期再開はスレッドごと。新しいスレッドの前に古いほうを止める。改訂なら同じスレッドに貼り直す |
| 親が最初に読んだ古い指示書のまま動く | 改訂後も親の動きが変わらない | worker 向けの規則は §1・§6 に置く（毎回読み直される）。親の手順を変えたら貼り直す |
